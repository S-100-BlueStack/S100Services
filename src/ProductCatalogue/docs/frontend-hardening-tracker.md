## Preservation and release boundaries

1. **Source and identity:** Keep the registry/capability model and `{ sourceId, productKey }` stable. Missing/ambiguous identity fails closed. Development mock sources are not production APIs. One source may not borrow another source's transport or mutation contract.
2. **Product workflows:** Product search owns Product lookup/selection/popup. Locator owns place search and map navigation. Analyze, Review, Product Collection, Timeline/History, filters, notices and popup actions retain their separate state owners.
3. **Async ownership:** One logical request has one generation/session owner. On source deactivation, popup close, route teardown or refresh, superseded work cannot publish stale Product, focus or status state. A failed refresh of an already active source should preserve the last successful representation where the accepted contract requires it.
4. **Presentation versus authority:** The map AOI source owns geometry and status. Product-detail enrichment must not silently rewrite AOI truth. Backend job/status/mutation/report contracts remain authoritative. Do not expose dispatch or artifacts without verification.
5. **Interaction:** Preserve UI behavior in light/dark mode, keyboard/Enter/Escape/focus, tooltip identity, accessible names, and reduced-motion behavior. Native input must not lose focus from incidental rerenders. Prefer public ArcGIS/Calcite APIs.
6. **Delivery:** Run `cd src/ProductCatalogue; npm run format; npm run check` locally before commit and a separate browser/deployment smoke pass before demo acceptance. Do not claim a check was executed merely because this tracker was updated.

# FI-018E — Repository Release Hygiene and Synthetic Development Fixtures

Implementation baseline: `ddff4b737554eebbcc06900527ab7dd0750d64b0`.

## Scope

FI-018E removes repository-only/generated artifacts that are not part of the supported Product Catalogue runtime and replaces legacy Product-derived Development fixtures with small synthetic fixtures for the two sources that still need mocks: Paper Charts and S-102.

Third-party licensing and redistribution decisions are intentionally outside this implementation. Repository-history cleanup is also outside scope; this change cleans the tracked tree going forward.

## Repository hygiene

The tracked `src/ProductCatalogueAPI/exports/` sample output is removed. Runtime exports remain ignored by the existing repository rule and continue to be generated by the API when export workflows run. No export runtime code or FI-018C1 compiler contract is changed.

The unused Vite starter assets `public/vite.svg` and `src/javascript.svg` are removed.

The Product Catalogue frontend no longer depends on `express` or `node-expose-sspi`. They had no Product Catalogue runtime/build consumer; `package.json` and `package-lock.json` are updated through npm. This does not change the separate `src/JobManager` dependency boundary.

The tracked `.env.development` keeps local API/Locator defaults but uses neutral branding. Organization-specific Development branding belongs in `.env.development.local`; the repository's existing `*.local` ignore rule keeps that file untracked.

## Synthetic mock contract

Only these mock routes remain:

```text
GET /mock/paper-charts -> mock/paper-charts.geojson
GET /mock/s102         -> mock/s102.geojson
```

The two small synthetic fixtures are embedded into the API assembly with explicit logical resource names. This keeps mock loading independent of `ContentRootPath`, Visual Studio output-platform folders, and copied `bin` content. Development continues to register the routes automatically. Non-Development test deployments can opt in with `MockDataSources:Enabled=true`; the repository default remains disabled.

Frontend exposure is independently controlled at build time. Development builds continue to expose the mock sources automatically. A production-mode test build can opt in with `VITE_ENABLE_MOCK_DATA_SOURCES=true`. Both frontend and API opt-ins are required for end-to-end use outside Development. Neither setting grants backend mutation/export capabilities to Paper Charts or S-102.

The old generic `/mock/products` route is removed because compatibility Product data now comes from the real backend path.

Both retained files are intentionally small synthetic GeoJSON FeatureCollections. Their identifiers, Product names, and rectangle geometries are created for testing and are not derived from production/chart data. The source registry, source-aware identity normalization, capabilities, filters, Product search, Product Collection, Analyze, and Review contracts remain unchanged.

The obsolete repository-level `artifacts/products.geojson` and `artifacts/some_products.geojson` copies are removed.

## Preservation

This implementation does not change:

- FI-018B frontend deployment configuration or truthful Analyze failures;
- FI-018C1 configuration/startup/compiler behavior;
- FI-018D1 detection disable/retry safeguards;
- detection enablement or enabled detection domain behavior;
- production authentication/authorization;
- supported Product/export backend contracts;
- canonical Analyze/Review routes;
- Paper Charts or S-102 backend contracts, which remain unavailable.

```

```

Manual verification should confirm both boundaries: Development still exposes Paper Charts and S-102 without extra configuration; a production-mode test deployment exposes them only when both mock opt-ins are enabled; `/mock/products` remains absent.

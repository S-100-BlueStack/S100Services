EXISTING FLOW AND INTEGRATION
UploadController/UploadSingularProductJob reserve an immutable ProductRevision in
ProductIcEncDelivery, then send its stored ExchangeSet through FTPS. Sending is
not validation. Simulation with both modes selected now reserves marked synthetic deliveries and processes candidate decisions without external transport.

The new adapter records actual outgoing dataset members, SHA-256 and S-57 CRC-32
in the reservation transaction before transfer. It does not guess checksums for
historical deliveries. SHA-256 covers each member's exact bytes. The original
ExchangeSet artifact retains auxiliary files and the complete transmission.

The worker's new Hangfire job captures Graph delta pages in IcEncInboundEmail.
Only after every relevant message on a page is durable does ValidationMailboxSync
advance. Pending messages are parsed/matched on the next tick. Repeated immutable
IDs cannot replace original evidence; read/unread flags are never consulted.
The same Hangfire distributed lock excludes polling, replay and operator review
across machines. The configured API and worker must share their Hangfire store.

Accepted/Rejected calls IIcEncAcknowledgementService, exactly as the existing
manual endpoint does. That repository rechecks the current immutable revision,
version, delivery and candidate state inside its transaction. RejectedByIC-ENC is
recorded with the existing IC_ENC_REJECTED error category. Both current deliveries
must be accepted before FinalizeEncPackageJob publishes the pair in S-128.

The existing finalizer writes S-128 first, then completes SQL. Failed enqueueing
and failed SQL completion are recovered by the existing DPC finalization scan;
S-128's package-ID/hash marker avoids duplicate attachments. Keep DPC recovery
enabled, or explicitly requeue FinalizeEncPackageJob after a failed finalization.
No SQL transaction is claimed to cover S-128. No new publication path is added.

Registered is receipt evidence only. Registration XML errors are visible as a
review warning and are not final rejection. PendingConditions remains InTransit
at candidate level and is visible in inbound review, never package Hold. This
preserves the five package statuses and independent S-57/S-101 outcomes.
The existing package IssueDate publication behavior is retained. DateValidated
and ExpectedReleaseDate are stored separately as calendar dates, without an
invented UTC time. No state action is derived from corrective-action prose.

MICROSOFT 365 PREREQUISITES
This implementation targets global-cloud Exchange Online/Microsoft Graph v1.0.
For on-premises Exchange or another host, implement IValidationMailbox with the same
bounded pagination and durable checkpoint contract; do not enable this Graph
adapter against an unsupported mailbox or fall back to username/password auth.
Managed identity is not implemented; the shipped unattended mechanism is a
certificate in Windows LocalMachine/My. Use a suitable managed-identity adapter
if hosting later moves to an environment where that identity is available.

Create a dedicated Entra application. Upload the public RSA certificate under
App registrations > Certificates & secrets > Certificates. Install its private
key into LocalMachine/My on the worker host and grant only the actual Windows
Service identity read access to that key. Configure rotation/expiry monitoring.
No private certificate, password, client secret or token belongs in appsettings.

Use Exchange Online RBAC for Applications with Application Mail.Read scoped to
this shared mailbox. Mail.ReadBasic cannot read the report bodies/attachments.
Do not grant Mail.ReadWrite or Mail.Send. Entra application grants and Exchange
RBAC permissions are additive: a tenant-wide Entra Mail.Read grant would bypass
the intended mailbox-only scope unless independently restricted. Use a dedicated
application and remove broad grants. Check the enterprise SERVICE PRINCIPAL
object ID, which differs from the app registration object ID.

SENDER AUTHENTICATION IS A REQUIRED ADMINISTRATIVE CONTROL
An allowlisted From address is insufficient. Configure Exchange/EOP so external
messages cannot retain or inject the chosen X-ProductCatalogue-ICENC-Verified
header. Strip all external copies at the protected ingress boundary. Only a
subsequent protected rule/connector may stamp the configured marker for genuinely
authenticated IC-ENC traffic delivered to this mailbox. Validate the actual
IC-ENC sender and the tenant's anti-spoof/DMARC or authenticated connector results
at that trusted boundary. Never stamp solely because a user-controlled From or
Authentication-Results string claims success. Your Exchange administrator must
implement and verify this tenant-specific trust policy; the application cannot
establish its authenticity from arbitrary internet headers itself.

Test a forged sender and a forged marker: neither may reach the mailbox with a
valid protected marker. The application also requires equal From/Sender SMTP
addresses, an exact allowlist entry and exactly one marker. Forwarded messages,
missing markers and display-name spoofing go to review. Keep DryRun=true until
these tests pass. No tenant changes have been attempted by this delivery.

SIMULATION MODE
Merge appsettings.ValidationEmail.simulation.example.json into the settings of BOTH API
and Worker and restart them:
  "SendToIcEnc": { "Mode": "Simulation" }
  "ValidationEmail": { "Mode": "Simulation", "DryRun": true }

Mode meanings:
  Disabled   No scheduled polling or simulation processing.
  Simulation Generate synthetic responses after simulated sends or explicit API
             requests; process only synthetic queued messages. Never read Graph,
             or contact the transport. Package Send reserves a permanently marked
             simulated delivery, moves the member InTransit, stores its generated
             response/report and applies matched final decisions to SQL state.
             Both accepted members use normal S-128 finalization and return Idle.
             No Graph credentials are needed. Use the intended test databases.
  Live       Read the configured shared mailbox. DryRun=true previews decisions;
             DryRun=false additionally requires the live rollout/auth controls.

Apply Data/Migrations/012_AddSimulationDelivery.sql to the System database
before deploying this version. Existing sends are marked live by default.
The creation script includes this column for new databases.

The package popup reads CanSend from GET /electronicproducts/packages/{source}/actions.
POST /electronicproducts/packages/{source}/send with {"packageId":"<active-guid>"}
requires the distribute policy and queues both Ready, error-free members with their exact
immutable revision IDs. GET /electronicproducts/packages/send-jobs/{jobId}
reports completion. The production frontend no longer needs a Vite demo flag.
Pause, discarded packages, manual holds and stale snapshots still block sends.
Both members are validated first. One SQL transaction commits both permanently
marked simulated deliveries, manifests, InTransit states and history. An invalid
sibling artifact rolls the whole attempt back; neither member is sent. Generated
responses are captured after that commit, then processed. A retry of the SAME
Hangfire job resumes its already committed pair and captured random outcomes;
it does not authorize a new Send while either member is InTransit.

The Worker records a simulated send, generates one random reply per member and
immediately runs the normal parser/matcher/acknowledgement pipeline. Its minute
poll recovers pending captured responses. The same job ID reuses its reservation
and captured outcome on retry, including after a connection loss during capture.
The singular /Upload/{datasetName} route rejects active ENC package members:
use package Send so an individual request cannot bypass paired dispatch. It
remains available for standalone products. Aggregate Send is Simulation-only in
this baseline; paired live transport is not introduced by this correction.

ValidationEmail:DryRun applies to live mailbox decisions and standalone previews.
It does not suppress state changes for explicitly reserved workflow simulations.
A registration or pending-conditions reply is recorded/reviewed and leaves its
member InTransit; it is never treated as unconditional acceptance. A rejected
reply puts its member/package into Error. Two accepted replies trigger existing
idempotent S-128 publication. That publication and SQL finalization remain separate
recoverable operations, not one cross-store transaction.

Four outcomes are equally likely: Registered, Rejected, Accepted and
PendingConditions. Within Rejected one of four supplied report scenarios is
selected, and within PendingConditions one of two holding scenarios is selected.
This covers all eight original sample variants. Dataset name, edition/update and
CRC come from the actual immutable candidate and stored exchange set; response
metadata is not copied from unrelated sample products. S-101 synthetic reports
omit an unverified CRC rather than applying S-57 checksum semantics.

To generate another response explicitly, use Swagger:
POST /upload/icenc-emails/simulate
  {"RequestId":"<new-guid>","DatasetName":"<actual-candidate-name>","ProductSpecification":"S57"}
ProductSpecification can be S57, S101 or omitted when unambiguous. The caller must
have the existing distribute policy. No operator key is needed for this preview
operation. A current candidate and its stored exchange set are required. Reuse
the same RequestId for an idempotent replay; use a NEW RequestId to roll another
random response. Reusing it for a different product/version is rejected.

Inspect the returned original synthetic message and then:
GET /upload/icenc-emails?isSimulation=true
GET /upload/icenc-emails?isSimulation=true&status=DryRun
The Worker parses/matches pending generated messages on its next minute tick.
The mode does not create unsolicited responses for every ready product.

Permanent IsSimulation and SimulationWorkflow evidence survives restart. Workflow
responses match only ProductIcEncDelivery rows with is_simulation=1, the exact
recorded delivery ID, current candidate revision, filename/version and checksum.
The acknowledgement service requires both modes to remain Simulation and records
Source=Simulation. Generated mail can never acknowledge a live delivery, and real
mail cannot acknowledge a simulated delivery. Mixed live/simulated acceptances
cannot publish as a pair. Changing to Live leaves simulated pending mail alone.
The explicit /simulate preview API remains read-only; it cannot authorize a
workflow send or promote its generated result into a real notice.
Original reports and bodies remain explicitly marked SIMULATION.

OPERATOR API (existing distribute policy applies)

  Latest 100 audit summaries; raw ResultJson contains extracted evidence/reasons.
GET /upload/icenc-emails/<inbound-guid>
  Original normalized metadata/body and original report bytes as base64.
POST /upload/icenc-emails/<inbound-guid>/review
  Header X-ICENC-Operator-Key uses the existing live operator key.
  Body: {"DeliveryId":"<verified-exact-transmission-guid>","Reason":"<verification explanation>"}
  Records the operator/association before retrying; still obeys DryRun. It cannot
  override contradictory parsing or a filename/CRC mismatch. Interrupted reviewed
  applications retain their verified association for the durable retry queue.
POST /upload/icenc-emails/replay
  Body is a normalized message JSON from the offline converter. Always previews,
  never puts synthetic messages on the live queue and ignores supplied trust.

RETRY AND MONITORING
Pending rows survive restart. A transient decision/storage failure delays retry
five minutes; review rows never auto-retry or auto-rebuild. A successful decision
followed by a failed audit completion reuses the same inbound event ID on retry.
Graph 429/5xx responses retry up to three times with Retry-After. Long retry waits
are deferred to the next minute tick. Failed message retrieval leaves its page
cursor unchanged. A message deleted between enumeration and retrieval becomes a
durable MESSAGE_UNAVAILABLE review record. Expired delta tokens replay from the
original saved initial boundary. The mailbox folder must retain/make messages
available until ingestion; a mail rule moving/removing them before retrieval can
only produce review evidence, not recover content that is no longer accessible.

Logs contain inbound ID, dataset filename, revision ID, delivery ID, outcome and
reason codes. HTTP-client automatic logging is disabled for delta/token URLs;
audit logging redacts replay bodies, review explanations and operator keys.
Monitor Pending/INFRASTRUCTURE_FAILURE rows, Review rows, stopped/failed Hangfire
polls, certificate expiry, delta resets and the existing finalization job/DPC.

LIMITATIONS AND ROLLBACK
No SQL Server migration execution, real Graph/certificate/EOP configuration, live
FTPS/ArcGIS/S-128 integration, full Windows solution build, or Windows BAT execution
was performed here. Run those deployment checks on the intended non-production
target before live use. API source syntax was compiled in an isolated harness;
that is not a full production solution build.

The parser supports current S-57 and S-101 dataset names and observed OOXML P007
and DMDLOAD templates. Binary Word, PDF, encrypted or new templates require review.
S-101 checksum-bearing responses require a verified S-101 checksum adapter; no
S-57 checksum semantics are silently reused for S-101. Missing CRC can match only
when filename/edition/update identifies one historical manifest-backed attempt.
Future unsupported templates fail closed. A material new IC-ENC template requires
new fixture evidence and review before changing the parser.

Rollback by stopping Worker, setting Mode=Disabled/DryRun=true and restarting it
(to remove the recurring schedule). Keep the additive tables and captured audit
history; older binaries ignore them. Accepted candidate/publication changes are
not undone by disabling email ingestion. Retain the existing recovery workflow.

# ENC S-101 compiler output paths

## Scope

The local `s100compiler` upgrade on 14 October 2026 changed the exchange-set
layout under the existing candidate edition directory. This document describes
how the Product Catalogue export pipeline locates the new output, archives it,
validates it, and cleans up discarded candidates.

The change does not alter S-57 compilation, SevenCs validation criteria,
export business rules, package lifecycle, SQL persistence, or Send/Accept.

## Compiler layout

The current observed output for `101DK001OSTSO`, edition 1, update 000, is:

```text
<output-root>/101DK001OSTSO/1/
  temp_101DK001OSTSO.yaml
  1OSTSO_000.idx
  101DK001OSTSO/
    S100_ROOT/
      CATALOG.SIGN
      S-101/
        DATASET_FILES/
          101DK001OSTSO.000
```

The extra dataset-specific directory is generated by the compiler. `CATALOG.SIGN`
is expected inside that directory's `S100_ROOT` (verify its location during the
next local compiler run). Staging YAML and the explicitly configured `-l` index
path remain under the edition directory, outside `S100_ROOT`.

## Contract

- `ExportOutputPath.GetCandidateDirectory` remains
  `<output-root>/<dataset-name>/<edition>` for S-101, preserving compiler
  invocation (`-d`) and staging/index paths.
- `GetS101ExchangeSetDirectory` returns
  `<edition>/<dataset-name>/S100_ROOT`; `GetS101DatasetFilesDirectory`
  returns its `S-101/DATASET_FILES` child. SevenCs uses the latter.
- `ReadS101ExportResultAsync` requires a non-empty `.000`/`.NNN` output in the
  new location. The compiler index stays a separate artifact. `CATALOG.SIGN`
  is read from the new exchange-set root.
- The archived exchange set still starts with **one** `S100_ROOT/` directory;
  neither the compiler's outer dataset directory nor staging/index files are
  included in the ZIP.
- Retried updates and update Discard remove only the candidate `.NNN` file in
  the new location. A discarded new edition removes the edition directory.
- Old-layout output is **not** silently substituted for missing new-layout
  files. If an existing edition was compiled before the upgrade, confirm that
  its base `.000` is available in the new edition exchange set before relying
  on an update; never archive an incomplete exchange set.


After restarting the Worker with the new binaries, inspect a disposable
S-101 New Edition candidate. Verify the `.000`, `CATALOG.SIGN`, `.idx` and
archived `S100_ROOT/` entries independently. Confirm that SevenCs starts with
`<edition>/<dataset-name>/S100_ROOT/S-101/DATASET_FILES`. Known SevenCs
validation findings are unrelated and are intentionally not addressed here.
Verify Update and Discard behavior against a disposable edition when available.
